## 1. 五条引用规则（System Prompt 必须原样包含）

1. **只引适用证据**：过时、场景不符、与说法无关的证据不要引用。
2. **逐字引用**：`quote` 必须是证据原文的逐字连续片段，不得改写、不得拼接。
3. **覆盖**：断言的每一部分都要有证据覆盖；只覆盖一半 = 欠引，不允许。
4. **有证据必须引**：有直接证据支撑的事实断言必须引用，不许因谨慎而不引。
5. **无证据显式标未验证**：没有证据支撑的内容 `cites` 必须为 `[]`，并在 text 里明确写
   "不确定/没有依据"；禁止编造。

> 规则 4 与规则 1 是**对冲**关系：只写"宁可少引"会导致过度克制（覆盖下降），
> 只写"必须引"会导致过度引用。两条必须同时存在。

## 2. 输出 schema（`segments-v1`）

```json
{"answer_segments":[
  {"type":"narrative","text":"..."},
  {"type":"claim","text":"一句完整、可独立阅读的断言",
   "cites":[{"evidence":"E1","quote":"证据原文的逐字连续片段"}]}
]}
```

约束：
- `type` ∈ {`narrative`, `claim`}；删除/改写以 claim 为单位，**一个 claim 必须是一句**。
- `cites: []` = 无记忆依据（阶段三映射为「个人推测」语域）。
- `evidence` 只能取上下文给出的证据编号（E1..En），不得编造。
- 输出必须是纯 JSON（无 Markdown 代码块、无解释文字）；解析失败按"本探针生成失败"记账，
  **不得静默当作无引用**。

## 3. 阶段三对 schema 的处理（确定性）

| 模型输出 | 判定 | 渲染 |
|---|---|---|
| claim + cites，enforce verified | A | 原样保留（锚点） |
| claim + cites，degraded | B | 断言 + 短原因说明（按 degrade_reason） |
| claim + cites，rejected | C | 删除该句，原句位留省略标记（保连贯） |
| claim + cites=[] | D | 「以下是我的个人推测：」前缀 |
| 全删且无 narrative | — | 兜底「这件事我无法给出可核验的依据。」 |

## 4. 版本与评测

- Prompt / schema 版本记录在评测 JSON 的 `meta`（`prompt`, `schema`, `model`）。
- 换模型、改规则、改 schema、改证据池构造 → 必须重跑三率（引用精度/覆盖率/过度克制率）。
- 生成模型调用必须限速：单条间隔 ≥3s、顺序执行、429/5xx 指数退避；批量评测需可续跑。
- **复跑脚本与评测语料不随仓库发布**：公开仓库只提供协议与 schema；私有语料与逐题产物永不导出。
