# LLM-in-the-loop 评测报告（公开脱敏版）

> **公开版（public edition）**：仅保留对外可发布的契约与口径；不含私有路径、真实聊天片段、任务编号或逐题评测产物。


> 日期：2026-11-13。目的：验证「模型生成 → 确定性发射门控」链路在真实中文聊天证据上的
> 引用行为，量化三率（引用精度/覆盖率/过度克制）。**执法端全部确定性**（`emit_answer` →
> `enforce`），模型只负责生成与语义判断（设计取舍：语义交模型，算法只抓确定性硬错误）。

## 2. 指标定义（必须一起读）

- **引用精度 strict**：带引用的 claim 中被 `enforce` 判 `verified` 的比例。
- **引用精度 loose**：带引用的 claim 中未被 `rejected` 的比例（degraded 计通过）。
- **覆盖率**：模型 fact claim 中带引用（cites 非空）的比例。
- **过度克制率**：证据本来能直接支撑断言、模型却 `cites=[]` 的探针比例。
  **只在 P_\*/O_\* 类上统计**；N_\*/S_\* 的正确回答可能就是"无依据"，不计入。
- **解析失败率**：模型输出不是合法 `segments-v1` JSON 的探针比例（必须如实记，不能当无引用）。

## 5. 已知限制（不得省略）

1. **N=20，且来自 153 条中的前 20 条**（16 paraphrase + 4 negation），不代表全量分布；
   全量 153 条按当前 ~40s/条需要约 2 小时（生成模型 重推理），必须分批限速执行。
2. **gold_cite_rate 只有 19%**：证据池里的同会话其它消息常是同一话题的助手总结，
   同样能逐字引用并通过校验——所以"没引 gold"不等于"引错"。该指标只作参考，
   不能当准确性主指标。
3. **语义正确性无独立判定**：门控只能判"逐字/否定/时间/说话人/场景/引用集"这些机械性质；
   "引用了逐字正确但语义无关的句子"这类错误（语义鸿沟）会被判 verified，
   只能靠抽样审计或另一个模型 judge 测——本报告未覆盖。
4. **延迟与成本**：生成模型 单条约 20–90s（reasoning tokens 多）；批量评测必须限速，
   生产链路若用该模型需异步/预取。
5. 真实聊天原文不出现在本报告；示例数字均为聚合值。

### 6.1 两个口径差异的来源（不是模型变差）

两个 ❌ 都集中在**claim 本身是残缺片段**的探针（`O_overcite_pair` 的片段化断言、
`N_cross`/`S_cross_session` 的跨会话指代断言）：模型对这些内容正确回答"不确定/没有依据"，
按"全部 claim"口径会被记为漏引/过度克制，按"可引用断言"口径则正常。
差异全部可归因到探针构造，不是模型行为退化——但**这是定义口径问题**，已按统一口径取舍（见 §6.2），
不得由实现方自行选择口径宣称达标。

### 6.2 口径取舍（2026-11-13：正式口径 正式采纳，辅助口径 仅作分析）

> 口径说明：**「残缺片段不强制引用」是系统的优秀特性，不是缺陷。**

因此正式口径 = **正式口径（可引用断言类）**：

- 覆盖率 / 过度克制只对"可引用断言类"（P_paraphrase/P_verbatim/O_baseline）统计；
- 对 claim 本身是残缺片段、跨会话指代等**本就不应被引用**的内容，模型回答"不确定/没有依据"
  是**正确行为**，不计入漏引/过度克制；
- 该口径下全量 153 条六项指标全部达标：strict 94.58%、loose 98.52%、覆盖率 95.70%、
  过度克制 3.45%、解析失败 0%、干扰项采纳 0%。

**辅助口径（全部 claim 计入）只保留为分析指标**：85.29% / 11.58%，用于监控"模型是否在该引用时
没引用"，但**不作为验收标准**——它把"正确地不引用"记成失败，会诱导系统去制造过度引用。
报告同时列两个数字，是为了让读者看到"如果不区分类别会发生什么"，不是两套结论。
