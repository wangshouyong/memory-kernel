## 1. 命名（固定）

| 层 | 名称 | 内容 | 写入 | 可变性 |
|---|---|---|---|---|
| L0 | 原始轨迹 | 逐字情景单元 | 只追加 | 不可变 |
| L1 | 锚定记录 | 哈希链上的 AnchorRecord | 只追加 | 不可变 |
| L2 | 引用事件 | 每次引用的判定与归因 | 只追加 | 不可变 |
| L2a | 审计与结算 | 审计结果、删除事件、结算结果 | 异步追加 | 不可变 |
| F1 | 锚定事实 | 从 L1 抽取并**确定性锚定**的原子事实 | 追加 / 以 supersede 修正 | 可修正，不可删除 |
| P2 | 画像与场景 | 从 F1 可重建的投影 | 版本化快照 | 可重建 |

**硬规则**：
1. L 系（存储）与 F/P 系（内容）命名不得混用。
2. 引用执法只面对 `(l0_anchor, quote)`；F1 的 `fact_id` 只是溯源索引，**不是执法对象**。
3. P2 永不直接作为引用锚点；被引用时强制展开到 F1 → L0。

## 2. 记录 schema（固定）

### 2.1 L0Record / AnchorRecord

| 字段 | 语义 | 参与内容哈希 | 参与记录哈希 | 参与签名 |
|---|---|---|---|---|
| `id` | 全局唯一 | — | ✔ | ✔ |
| `seq` | 单调递增 | — | ✔ | ✔ |
| `content` | 逐字原文（NFC） | ✔ | ✔ | 经 content_hash |
| `content_hash` | SHA-256(content 的 UTF-8 字节) | — | ✔ | ✔ |
| `char_span` | 在来源中的码点区间 `[l, r)` | — | ✔ | ✔ |
| `content_fragment` | 被引用的逐字片段（quote 的存储形式） | 由 content 派生 | ✔（派生） | ✔ |
| `source_id` | 轨迹/文档标识 | — | ✔ | ✔ |
| `episode_id` / `turn_index` | 情景边界与顺序 | — | ✔ | ✔ |
| `modality` | text / image_ref / audio_ref / video_ref | — | ✔ | ✔ |
| `speaker` | 归属主体 | — | ✔ | ✔ |
| `record_hash` | 见下 | — | — | ✔ |
| `prev_hash` | 前一条的 `record_hash` | — | ✔ | ✔ |
| `signature` | 见下 | — | — | — |

**哈希与签名的分工（修正 N1）**：
- `content_hash = SHA-256(content_bytes)` —— 只回答"内容是否被改"。
- `record_hash = SHA-256(prev_hash_bytes ‖ canonical_json(全字段))` —— 回答"这条记录是否被改"。
- `signature = HMAC-SHA256(K_store, id ‖ char_span ‖ content_hash ‖ record_meta_hash)`
  —— **签名必须覆盖谓词会读取的每一个字段**（speaker、polarity 等），否则在线校验会放过元数据篡改。
- 记法：**签名保完整性，链保顺序与整体性。**

**坐标约定**：写入前统一 NFC；`char_span` 与引用 `offset` 均以 NFC 后的**码点**计，左闭右开。
引用 offset 相对 `content`，不与 source 坐标混用。

### 2.2 F1 AtomicFact（关键字段）

`fact_id / l0_anchor(id, span) / content_fragment / subject / predicate / object / polarity /
modality / temporal / speaker / ownership / conditions / quantifier / source_type /
status ∈ {active, disputed, retracted, superseded, quarantined} / supersedes`

- `quarantined`：锚定不合法或元数据缺失，**可存储、不可引用**。
  解除路径：重抽取产生新事实（`supersedes` 指向旧的），旧事实保持 `quarantined`——只进不出不存在，但出口是"追加"而不是"修改"。
- `content_fragment` 必须是 `l0_anchor.content` 的连续子串，且 span 落在 `char_span` 内。

### 2.3 未锚定窗口（U2：先写后锚）

写入即标 `unanchored` 并进入 pending 对账队列。`unanchored` **可检索、可引用，但 verdict 上限为 `provisional`**，不得升级为 `verified`。

1. 外锚恢复后 **TTL 内**完成对账（建议 24–72h，按业务风险定）。
2. 对账通过 → `anchored`，后续按正常路径升级。
3. 对账失败（root 不匹配 / 签名无效）→ `quarantined`，永久不得升级。
   **隔离范围 = 断裂点之后的全部记录，不是单条**——单条隔离会让断裂点下游仍被引用。
4. TTL 超时未对账 → `anchor_failed`，永久不得升级为事实；内容与锚定结构保留（**未锚定 ≠ 不存在**）。
5. 监控：`unanchored` 比例 / pending 队列长度 / 对账延迟 p99；持续超阈值才熔断为停写——**停写是最后手段，不是默认策略**。
6. 外锚不可用**不停写**；伪造窗口存在，但窗口内记录最高只到"保留"。
7. 表述："锚定服务是写入路径的**可用性依赖**；锚定延迟不影响记录可写，但影响记录可升级为『事实』的时间。"
8. **U7 已定**：外锚只证明"某时刻账本处于该状态"，**不证明"这些记录是谁写的"**。
   因此增加独立的写入方签名与身份准入，见 §2.4。

### 2.4 写入方归属（U7 设计记录 · **已取舍不提供，本节不属当前实现/承诺**）

**威胁模型（已确认）**：假设**持有合法签名密钥的写入方可能被攻陷**。

密码学做不到"阻止合法写入方写入"，只能拿到三件事：**归因、窗口、失效**。
任何"伪造记录进不了事实语域"的表述，都必须建立在"归属有效"这个前置条件上，而不是建立在时序上。

#### 2.4.1 两道门，不要混

- **写入路径 = 归属准入**（谁写的、能不能写）
- **引用路径 = 谓词执法**（引用是否合法）

两者不得合并实现，否则身份问题会被当成谓词问题处理，反之亦然。

#### 2.4.2 双签名：提交签名覆盖内容，账本签名覆盖位置

| 角色 | 密钥 | 签什么 | 证明 |
|---|---|---|---|
| 写入方 Producer | **Ed25519（必须非对称）** | `submission_hash = H(writer_id ‖ key_epoch ‖ writer_seq ‖ ts ‖ content ‖ metadata)` | 这条内容由谁提交，不可否认 |
| 账本 Store | HMAC（或 Ed25519） | `record_hash = H(prev_hash ‖ seq ‖ submission_hash ‖ content_hash ‖ …)` | 这条记录在链上的位置与顺序 |

- Producer **必须非对称**：对称密钥的持有者 = 可伪造者，无法提供不可否认性。
- Store 若需多方验证，同样改非对称。
- 存储方不再需要被信任为"作者"，只需被信任为"排序者"；而排序本身由外锚 checkpoint 约束。

#### 2.4.3 记录新增字段

`writer_id / key_epoch / writer_seq / ts / submission_hash / producer_sig / store_sig`

- `writer_seq` 是**每个写入方独立**的单调序号 → 用于检测写入方侧回滚与截断（全局 `seq` 做不到这一点）。
- `ts` 必须来自**受信时间源**（锚定服务 checkpoint 或 TSA）。没有可信时间，"窗口"无法界定，`undo` 也无从谈起。

#### 2.4.4 读路径校验策略（控制成本）

- **ingest 时**：验证 `producer_sig` + `store_sig`，把 `record_hash` 写入已验证摘要表；
- **每次读**：重算 `content_hash` 与 `record_hash` 并与摘要比对（O(1)），**不重复验签**。
- 记录不可变 ⇒ 验签结果可安全缓存；哈希比对不可省略。

#### 2.4.5 密钥注册表（只追加 + 透明）

`(writer_id, key_epoch, pubkey, valid_from, valid_to, status)` 只追加；
轮换与吊销都通过**追加新条目**完成，不修改历史条目。
可选：把注册表 root 一并外锚，使"密钥变更"本身也公开可审计。

#### 2.4.6 被攻陷后的处理：不能删除，可以失效

- 吊销事件追加进 L2a：`revoke(writer_id, key_epoch, detected_at)`；
- 影响范围：该 `(writer_id, key_epoch)` 且 `ts ≥ detected_at − τ` 的记录，verdict 上限降为 `quarantined`
  （不是"保留"——归属本身已不可信，保留级仍隐含"这是真的记忆"）；
- 已发射输出**不追溯**（N5）；后续引用按新上限执行。

#### 2.4.7 窗口怎么压：心跳证明

写入方周期性签名"key 在 T 时刻未被攻陷"的心跳证明。
**归因延迟 τ**（= 心跳间隔 = 吊销传播时间 = 伪造窗口上限）是唯一需要定的参数，
它与锚定周期、密钥世代长度一起构成同一族安全预算。

#### 2.4.8 残余风险（必须写进文档，不许用密码学盖住）

1. 同时持有 producer 密钥**与** store 密钥的人可完整伪造——只能靠职责分离、双人控制等**组织控制**，不是密码学。
2. 被攻陷的写入方可以写入**貌似合理**的内容——密码学只给归因，不给语义真假。
   这恰好是执法层存在的理由，而不是它被替代。

#### 2.4.9 成本

新增：密钥管理、注册表/透明日志、每次写入多一次非对称签名、心跳与吊销传播。列入 §8 预算表。

### 2.5 可归因承诺（U13 设计记录 · **已取舍不提供：不承诺「可归因」；本节不属当前实现**）

**承诺正文（建议原文，不得改写为更强表述）**：

> 对每一条进入账本的记录，系统可提供
> `(writer_id, build_version, key_epoch, submission_hash, ts, producer_sig, inclusion_proof, causal_origin)`。
> 任何第三方在**不信任本系统基础设施**的前提下，可独立验证：
> (a) 该内容由该写入方在 `ts` 时刻提交；
> (b) 该记录被包含在某次已外锚的 checkpoint 中；
> (c) 该写入方密钥在 `ts` 时刻未被吊销。

#### 2.5.1 三条必要条件

1. **第三方可验证**：公钥注册表与 checkpoint root 必须公开归档；验证规范（字节级规范化、签名域分隔、inclusion proof 格式）必须独立成文，
   不能只存在于实现里——否则"可归因"只对本系统成立，属于自证。
2. **归属证明不得依赖内容可读**：验签只需要 `submission_hash` 与 `producer_sig`。
   内容与 `submission_hash` 的一致性，在 crypto-shredding 之后**不可再验证**。
   ⇒ 承诺只能写"可归因"，不能写"内容可复核"。
3. **双层归因**：`writer_id`（技术写入方 + 构建版本）与 `causal_origin`（session / user / turn / tool）都必须在签名元数据内。
   只记"哪个服务写的"而不记"从哪段会话来的"，归因无法落到具体事件。

#### 2.5.2 四条边界（必须与承诺同时发布）

| 边界 | 后果 |
|---|---|
| 迁移前记录 | 无写入方签名 → **不得称为"可归因"**；以 `legacy_writer` 伪身份标注并降级语域，或排除出承诺范围 |
| 已 shred | 归属记录在案，但不可重验 |
| 已吊销密钥 | 仍可归因，但可信度降为 `quarantined`——**可归因 ≠ 可信** |
| 时间精度 | `ts` 精度受锚定间隔约束；未锚定窗口内的时间只能事后由 checkpoint 区间界定 |

#### 2.5.3 两个结构性冲突

1. **删除权 vs 可归因**：若归因元数据含个人标识，删除请求会与"可归因"直接冲突。
   唯一出路是**元数据最小化 + 伪名化**（`writer_id` 用伪名，映射表单独加密并受删除权约束），
   并在条款中明写"归属记录可能因删除请求而不可用"。这一条与 §2.4 的"不能删除，可以失效"是同一原则的延伸。
2. **归因 ≠ 问责**：系统只能定位到写入方，不能替代责任。必须有写入方准入审批与事故响应流程，否则归因只是一串 ID。

#### 2.5.4 承诺切换后的验收标准

验收从"引用对不对"扩展为两条并列：

1. 引用执法：§5 的六条性质；
2. 可归因：**第三方仅凭公开材料**（注册表 + checkpoint + 验证规范）能独立验证 §2.5 承诺正文的三项。

第 2 条由外部方执行，不由本系统自评——这是承诺与"自我声明"的分界线。

## 3. 执法层（固定）

### 3.1 两级准入（复杂度预算的落地）

| 层级 | 准入条件（全部满足） | 例子 | 预算审查 |
|---|---|---|---|
| **Tier 0** | ① 零模型依赖 ② O(n) ③ **已论证单侧**（附对抗用例） ④ 谓词定义域写进规范 | verbatim、preserve_negation、preserve_temporal、preserve_speaker | 免预算，但受"谓词总数上限"约束 |
| **Tier 1** | 需实测收益 > 成本；估不出来 → 降为监控项 | 联合一致性、骨架检查、组合约束、经验联想校准 | 走预算 |

> **"单侧"不是零模型依赖谓词的天然属性，必须逐谓词论证。**
> `verbatim` 严格单侧（子串匹配不会把非子串判成子串）。
> `preserve_negation` / `preserve_temporal` 只是**条件单侧**：词表漏掉"未必/谈不上/至今/此前"就会产生假接受。
> 因此它们的单侧性以"词表 recall 在定义域内 = 1"为前提，该前提必须由 gold set 度量。

### 3.2 必检集的来源（修正 P0-3 / N2）

- **表面层（硬）**：从 L0 原文的表面特征确定性编译——否定词表、时间词表、归属动词表、条件标记表。
  **不读 F1 元数据，零模型依赖。**
- **元数据层（软）**：从 F1 元数据确定性编译——`quantifier → no_generalization`、`source_type → source_attribution`、`conditions → scope`。
  只允许产生**降级**，不允许产生**事实资格**。
- **保守编译规则**：元数据不确定时**照样编译**该谓词。
  多编译 → 假拒绝（可测、可调）；漏编译 → 假接受（不可逆）。不对称性写成硬规则。

### 3.3 判定与覆盖率（修正 P0-4 / N4）

```
verdict_semantic ∈ {verified, degraded, rejected}      # 纯函数
coverage         = { policy_version, sampling_rate, decision_seed, stratified_bucket, full_checks_ran }
emitted_state    = f(verdict_semantic, coverage)       # 见 §4
```

- `verdict_semantic` 是 `(claim, evidence, predicate_version)` 的纯函数；
  **前置条件**：evidence 的写入方归属有效（未吊销、`ts` 不在吊销窗口内）。
  归属失败直接落 `rejected(untrusted_writer)`，**不进入谓词判定**——身份问题不能被当成谓词问题处理。
- **`provisional` 不是 verdict**，它是 `coverage.full_checks_ran = false` 的标注，避免伪装成一次判定；
- **锁定时刻**：发射前最后一次执法完成时，快照 `predicate_version / policy_version` 进 L2，此后状态不可变；
  锁定后发生的任何异常记为完整性事件，不改变已锁定状态。

### 3.4 修复链（修正 P1-11 / N7）

```
硬失败 → 重生成（上限 N 次，确定性回灌失败原因）
      → 收窄（只删附属子句，不得改断言类型、主谓宾、polarity、speaker）
      → 降级为 memory_uncertain
      → memory_unverifiable（或拒答）
```

- 收窄后**必须重新走完整执法**，不得沿用原 verdict；
- 收窄链长有上限，记录 `narrowed_from`；
- `repair_attempts / tokens_spent` 写入 L2；
- **预算耗尽时禁止静默接受最后一次收窄结果**——终态只能是降级或 unverifiable。

### 3.5 Tier 1 极简骨架（已实现并实测）

Tier 0 只保证"忠实地指向某条记录"，不保证"这条记录支撑这个断言"。Tier 1 补这一层，规则两条：

1. **内容词接地率**：断言的内容词（含被引用记录的 speaker 元数据）在引用证据中的覆盖率 ≥ τ；
2. **时间论证接地**：断言里**每一个**时间论证（绝对日期或相对时间）都必须能在证据里找到兼容锚点。

判定归属：**骨架失败 = `degraded`（软失败）**，不是拒绝。它证明"证据不足以支撑该断言"，
不能证明"引用是伪造的"——伪造归 Tier 0 的 `verbatim`。

实测（LoCoMo 1762 对 / LongMemEval 465 对，见 `<固定评测产物，不随仓库发布>`、`评测报告`）：

| 场景 | Tier 0 | Tier 0 + Tier 1（τ=0.8） |
|---|---|---|
| 断言取 A 内容、引用指向 B（wrong_evidence） | 100% 漏检 | **100% 拦截** |
| 同一话题只引用一半证据 | 无法发现 | **96% 拦截** |
| 正确引用误杀 | — | 0% |
| 脚本同义词改写的误杀 | — | 3.6%（**下界**） |
| 单次执法 p50 | 37 µs | 99 µs |

**参数固定条件**：τ=0.8 只在"断言由两段原文拼接"的构造集上验证过。真实模型改写更激进，
τ 必须在真实生成输出上按"忠实 claim 误杀 ≤5%"重新校准后才能锁定；校准前 τ 是**可调参数**，不是常量。
Tier 1 属贵检查，生产路径应走审计采样，不得全量执行。

## 4. 输出层（U1 已定稿：4 语域 + 措辞变体）

语域固定 **4 个：事实 / 保留 / 未知 / 推测**。语域之下用"措辞变体"区分原因，**不新增第五个语域标签**。

| # | 判定组合 | 语域 | 措辞变体（系统模板渲染，模型不参与选择） |
|---|---|---|---|
| 1 | `verified` ∧ `coverage.full_checks_ran = true` | 事实 | "根据记录，……" + anchor 引用 |
| 2 | `degraded`（软失败谓词触发） | 保留 | "我记得……，但这条在[时间/否定/归属]上可能有歧义。" |
| 3 | `coverage` 不完整（贵检查未跑 / `unanchored`） | 保留 | "我记得……，但这条我还没核实过。" |
| 4 | `rejected`，原因 = **检索为空**（负证据已入 L2a） | 未知 | "这件事我不记得了。" |
| 5 | `rejected`，原因 = **引用非法 / 锚定失效 / 已 shred / 写入方归属失效 / 修复预算耗尽** | 未知 | "我给不出可核验的依据。" + 完整性事件 |
| 6 | 无锚定 ∧ 命中经验 | 推测 | "按我过去的经验推测……" + `ref:experience/…` |
| 7 | 无锚定 ∧ 无经验 | 推测 | "按我的知识推测……"（零 anchor 引用） |

### 4.1 语域格序（优先级规则，修正 U1 缺口）

`事实 > 保留 > 未知 / 推测`。

```
emitted_register = min( register(verdict_semantic), register(coverage) )
```

即：**coverage 不完整时，即使 verdict 算出 `verified`，语域也必须压到"保留"**——否则组合断言的贵检查被跳过时会被标成事实。

### 4.2 措辞变体选择器

`(verdict_semantic, coverage, rejected_cause)` 三元组**确定性选模板**，不经过模型。

- `rejected` 必须携带 `rejected_cause ∈ {search_empty, invalid_anchor, shredded, untrusted_writer, budget_exhausted}`；
  第 4 行与第 5 行**必须分开渲染**——把"捏造引用/锚定失效"说成"我不记得了"是把生成器故障伪装成记忆缺失，
  既不可证伪，也丢掉了最该被抓住的信号。

### 4.3 硬规则

1. 模态 = `emitted_state`，由执法结果确定性派生；模型输出的是**提案模态**，被覆盖。
2. `memory_gap`（检索为空）必须携带负证据（query / 候选集 / 为空原因）；否则不可证伪。
3. 联想命名空间分离：`ref:anchor/…` 与 `ref:experience/…`。
   association **零 anchor 引用**、可带 experience 引用；experience 引用不走 L0/L1 执法，走经验注册表展开。
4. 经验联想必须给：校准后 precision + Wilson CI + 适用范围；超出范围自动降级为 `model_knowledge`。
5. **参数知识的"置信度"不得由模型自评**：要么给校准过的分档 + 校准集说明（含 CI），要么不标数字、只标"无记忆依据"。
6. **不承诺回访就不许写"后台正在确认"**：若无回访机制，措辞只能是"这条我还没核实过"。
7. `memory_fact` 的语义是"**在已论证的谓词定义域内通过**"，不是"内容为真"。

> **待取舍（U10）**：组合断言（骨架深度 > 1）即使全检通过，其结论也是**推理**而非摘录。
> 建议语域上限压到"保留"，深度检查通过后才允许"事实"；否则"根据记录"对推理结论是过度断言。

## 5. 六条可测性质（固定）

| # | 性质 | 定义 | 测试写法 | 残余风险 |
|---|---|---|---|---|
| P1 | **单侧性** | 在**已论证单侧且词表覆盖范围内**，不存在"通过校验但实为否定翻转/丢时间/丢主体"的摘录型引用 | 对抗集（翻转/删时间/换主体）pass 率 = 0 | 词表 recall 与 gold set 完备性；只能靠"对通过项抽样深检"估计漏检率 |
| P2 | **可复现性** | 同 `(claim, evidence, predicate_version, policy_version, decision_seed)` ⇒ 同结论与同采样决策 | 回放集重跑，逐条一致 | 语料版本漂移 |
| P3 | **可归因性** | 任一 rejected 可定位到 `(record_id, predicate_name, predicate_version, 失败片段)` | 拒绝原因字段完整性校验（schema 级） | 无 |
| P4 | **非空洞性** | 收窄只删附属子句，断言类型与核心三元组（含 polarity、speaker）不变 | 结构断言逐字段相等 | 三元组字段定义需固定 |
| P5 | **义务不替换** | 收窄后的通过来自保留部分的逐字证据，而非义务集变化 | 比较两次执法的 `obligation_set_signature`（含 predicate_version） | 无 |
| P6 | **有界性** | 修复链在确定性预算内终止，终态不是"静默接受" | `repair_attempts / tokens_spent` 必填 + 终态枚举校验 | 无 |

> 原"单调性"性质**作废**：它会把合法收窄判成违规，进而废掉整条修复路径。

## 6. 学习层（固定）

**一个审计统计层 + 三个消费者 + 两个性能启发式。**

- 统计层主键：`(predicate_name, predicate_version, claim_type, stratum)`。
- 消费者：
  - **schema 库**：图式匹配必须是**结构精确匹配**（claim 类型 × 义务集），统计只允许排序；无匹配时可退回从头构造证明，且覆盖率作为指标，fallback 率超阈值报"图式库退化"。
  - **谓词库**：判别力统计（fail 率、对 gold 的 precision / recall），驱动逐谓词消融与版本回滚。
  - **审计分配**：唯一被允许"学习"的地方。
- 性能启发式：搜索排序（势能只影响找证据的顺序，不影响选中哪条）、缓存衰减（不承担记忆语义）。
- **证据选择 = 确定性最优匹配**，不做探索。

### 6.1 对照组（必选，不是可选）

- 硬检查（哈希 / 签名 / verbatim / 否定）**无条件全量**，永不被采样。
- 贵的检查按成本分级，强制 5–10% 随机对照组走全检查。
- 采样率按目标精度反推：`n ≈ (1.96/ε)² · (1−p)/p`；对照组率 = n / 需要的流量。
- 分层单位 = `(谓词集合签名, 断言类型)`；每层设 `n_min`，不足则与同语义邻层合并并记录 `merge_chain`；合并后仍不足 → 输出 `unmeasured`，并计入"未覆盖污染面"总量。
- **污染率报告必须带样本量与置信区间；样本量不足时输出 `unmeasured`，禁止点估计。**
- 对照组**双用途**：① 估计污染率；② 估计谓词/词表的假阴性率。同一套仪器，两个指标。

## 7. 结算层（固定为互补层，不替代）

定位：**不是替代范式，是互补的一层**。核心价值不是"判定更准"，而是"判定过程顺带产出带真实结果的标注流"。

三条替代性主张**均不成立**：

| 原主张 | 裁定 |
|---|---|
| 结算使"发射时刻状态"变得天然 | ✘ 仅覆盖可证伪子集；偏好/历史事件不结算 |
| 结算替代污染率采样 | ✘ 只是改名；观测样本不可省，且不可结算多数仍靠对照组 |
| 结算可发现收窄退化 | ✘ 方向相反：收窄走向欠断言，结算只会更容易成功 |

**接入要求**：
1. 结算记录必须与引用事件对齐存 L2a，join key = `(citation_event_id, predicate_version, policy_version, claim_type)`；
2. 校准必须**按可证伪性类别分层**——结算标签本身有选择偏差，不可结算类仍只能靠对照组，不得混算；
3. 结算产出的标签是谓词校准、污染率估计、经验联想适用范围的直接输入。

## 11. 最小闭环的验收口径（防止误判）

最小闭环 = 锚定 + verbatim + 硬失败拒答。它**只测两个数**：

1. **捏造/漂移引用率**：约束解码 vs 无约束解码，成对比较（这是方案存在的理由）。
2. **逐字谓词的假拒绝率**：用户可感知的摩擦（决定体验是否成立）。

**禁止**用最小闭环测出的数当作"系统污染率"去定采样策略——只有 verbatim 的系统测不到失真类污染，结果不可外推。

## 13. 生产 IDF 策略（2026-11-13 取舍，D-IDF-1）

实测证据（`<评测产物，不随仓库发布>`）：用 **2% 语料**构建全局 IDF 后直接给全库打分，
跨会话检索 R@10 从 77.8% 掉到 **68.6%**（-9.2pp），14 条查询掉出 top-10；用 5% 语料建表 → 73.2%；
用到 20% 语料建表才与全量无差异。**静态 IDF 在生产环境不可接受。**

规则（生产级，不得跳过）：

1. **禁止陈旧 IDF**：生产环境不得"启动时建一次全局 IDF 后永久复用"。任何 IDF 必须能回答
   "它由哪一版语料构建、生成于何时"。
2. **允许两种更新方式**：
   - **定期全量重算**（推荐起步方案）：低峰期（如每天 03:00）用当时全量账本重算，构建期间旧版本继续服务；
   - **滑窗/增量维护 df**（长期方案）：append 时对应 token 的 `df += 1`，删除/遗忘时 `df -= 1`，
     按批或按时间窗口重算权重；必须处理浮点误差与并发写入。
3. **IDF 版本号**：格式 `idf-<yyyymmddHHMM>-<sha8>`（sha8 = 语料+参数摘要前 8 位）。
   **检索结果元数据必须携带 `idf_version`**，评测产物 `meta` 同样必须携带；没有版本号的检索结果视为不可审计。
4. **原子切换（双缓冲）**：新 IDF 构建完成后单次切换；切换窗口内允许新旧版本短暂共存，
   但每条结果必须标注它实际使用的版本；不得出现"部分用旧表部分用新表"却不标注。
5. **可复现性**：同语料 + 同 `idf_version` + 同查询 → 同排名；版本变化必须写进评测/审计记录，
   报告不得混用不同 IDF 版本的数字。
6. **监控**：`df` 漂移、单 token 的 `df/N` 突变、检索延迟 p50/p95；超阈值告警（IDF 更新失败必须可见）。
7. **回溯要求**：审计必须能回答"某条历史结果当时用的是哪个 IDF 版本"；旧版本不得被静默覆盖删除。

> 单机 Demo 可以不做动态 IDF，但**只要进入长期使用或 SaaS，就必须实现本节**。
