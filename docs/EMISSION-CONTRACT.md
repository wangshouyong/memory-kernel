# 生成-执法管线契约（三阶段：前置过滤 → 模型生成 → 发射门控）

> 设计取舍的"模型克制"架构。本文件把三个阶段的行为定死，便于实现与说明文档。
> 与既有代码的关系：阶段三复用 `memory_kernel/registers.py` 的四语域与措辞模板，
> 但需要新增**段落级组装/删除**能力；阶段一需要新增**记录级状态索引**。

## 0. 硬约束

1. 阶段一、阶段三**全部确定性**，不调用模型（公理 B）；只有阶段二调用模型。
2. 阶段三**禁止把模型原始输出直接透传**给用户；一律经过 `enforce()` 逐条校验后重写。
3. 任何"删除/过滤"都必须留审计记录（anchor、原因、阶段），不得静默丢弃。

## 1. 阶段一：检索前置过滤（纯算法）

输入：账本、当前上下文（`now`、当前会话 id、当前问题）、token 预算。
输出：`{records: [...], dropped: [{anchor, reason}], tokens_estimate}`。

### 1.1 过滤分三级（语义相关性过滤要求）

**一级：可确定性证明不适用**（必删，硬规则）

| 条件 | 判定 | 说明 |
|---|---|---|
| 已被更正（superseded） | 复用 v4.4 `scenario_superseded` 的「同一事实」判据，在**记录级**预计算：同 source/episode 存在 `turn_index` 更大、`speaker=="user"`、`zh_corrected` 且与被评记录内容词交集达阈值 | 记录级状态索引，入库/建索引用时算一次，可缓存 |
| 未来记录 | 记录时间 > `now` | 后事不可作前证 |
| 污染源 | source 标记为 contaminated（评测/项目语料） | 生产不应出现，防御性过滤 |

**二级：语义相关性过滤**（允许模型，检索阶段不属于执法）
- 用固定模型/固定分数的相关性打分（词面 BM25 / 字符 n-gram / 向量余弦，可组合），
  把**明显不相关**的记录从 Prompt 上下文里剔除；模型必须固定（记录 sha），判定可复现。
- 分级处理而不是一刀切：
  - 低分尾部（明显不相关）→ 直接剔除；
  - 中间灰区 → 保留但标注「低置信/待模型判断」；
  - 高分 → 原样保留。
- **必须做保留率门禁**：同一探针集上测「被过滤掉的 gold 证据比例」与上下文 token 节省。
  验收线（先定，实测可调）：**gold 保留率 ≥ 98%** 且过滤后 R@10 不低于过滤前 −2pp；
  任何阈值都必须带这两组数字，禁止只报 token 节省。

### 1.1.1 已校准的默认档（2026-11-13，153 条探针实测）

| 策略 | gold 保留率 | 过滤后 R@10 | 字符节省 | 结论 |
|---|---|---|---|---|
| 不过滤（基线） | 100% | 96.7%（**同会话 in-sample，不是检索能力**） | 0% | — |
| 删低分尾部 10% | 99.3% | 96.7% | 2.2% | 可用（最保守） |
| **删低分尾部 20–30%** | **98.7%** | **96.1%** | **5.2–8.5%** | **推荐默认档**（满足门禁） |
| 删低分尾部 40%+ | 96.1% 以下 | 93.5% 以下 | 20%+ | 突破保留率门禁，禁用 |
| 零分剔除（无任何词面交集即删） | **92.2%** | 90.2% | 11.1% | **否决**：转述类 claim 与证据无词面交集，零分 gold 被误杀 |

结论：阶段一默认 **按 RRF 分数删低分尾部 20–30%**（分档可配），灰区保留并标注「低置信/待模型判断」。
零分剔除看似"确定性安全"，实测反而最伤召回——这条必须写进实现与报告。

**三级：预算溢出**（只受 token 预算约束）
- 超过预算时按**廉价分数**从低到高截断，记录 dropped 与预算，不得与相关性过滤混淆。

**不允许**：用语义相关性做「不可解释的硬过滤」而不留阈值依据与保留率证据；也不允许把
「过滤掉就再也拿不回来」的内容当作不影响正确性——被过滤的候选必须进审计，必要时可回捞。
这与"检索候选集不裁剪"（保 R@k 分母）不冲突：**检索候选集不裁，Prompt 上下文按上面三级裁**。

### 1.2 保留信息

被剔除的记录以 `[已更正，不可引用]` 一行 stub 形式可选保留（默认关闭）：保留可帮助模型理解
"这件事被更正过"，代价是 token。默认按用户要求**直接剔除**，stub 开关留配置。

## 2. 阶段二：模型生成

输入：过滤后的上下文 + 用户问题。
输出：**结构化 JSON**（不是自由文本），因为阶段三要按断言逐条重写/删除。
完整 Prompt 规则、schema 与版本管理见 **`docs/PROMPT-CONTRACT-v1.md`**（`prompt-v1` / `segments-v1`）。

```json
{
  "answer_segments": [
    {"type": "narrative", "text": "..."},
    {"type": "claim", "text": "断言句（必须是完整可独立阅读的句子）",
     "cites": [{"anchor": "a_000123", "quote": "逐字片段"}]},
    {"type": "claim", "text": "无证据的推测性断言", "cites": []}
  ]
}
```

- `claim` 必须按句子切分（阶段三的删除以 segment 为单位；自由文本无法可靠切句）。
- `cites: []` 表示"无记忆依据"（阶段三映射到 `speculation` 语域）。
- Prompt 规则见 Prompt 契约：只引当前语境适用的直接证据、逐字引用、有证据必须引、
  无证据不得编造且必须显式标"未验证"。

## 3. 阶段三：发射门控与强制重写（核心，纯代码）

对每个 `claim` segment：调用 `enforce(ledger, Claim(citation=..., text=...), policy=v4, context=...)`，
按结果重写：

| 情况 | 判定 | 渲染（复用 registers.py 模板） |
|---|---|---|
| A verified | `verdict=="verified"` | 原样输出，保留锚点标记 |
| B degraded | `verdict=="degraded"` | **按 `degrade_reason` 分别措辞（v4.6 设计取舍：不用统一长前缀）**，形如「断言原句（短原因，仅供参考）」：over_citation / scenario_superseded / argument_mismatch / partial_evidence / cross_session / temporal / over_generalization 各有独立模板 |
| C rejected | `verdict=="rejected"` | **删除该 segment**；若删除后无任何 claim 且 narrative 为空 → 输出兜底「这件事我无法给出可核验的依据。」 |
| D 无引用 | `cites == []` | 前缀「以下是我的个人推测：」（registers: `speculation/model`） |

**调用方契约**：`EmitResult.audit` 的每条 claim 带 `state` 字段，取值
`verified` / `degraded` / `rejected` / `uncited`——**无引用（uncited）= 未验证**，调用方不得当事实
展示；`rejected` 的句子已被删除，只能从 audit 追溯。语义残差（逐字正确但语义无关等）不在
算法能力范围内，见 `docs/ALGO-CEILING.md`。

组装规则：
- `narrative` segment 原样保留（不参与执法）。
- **删句保连贯**：C 情况在原句位留省略标记「（此处省略一句缺少可核验依据的内容）」，
  避免上下文断层（首/尾标记与连续标记会被清理）；可用 `redact=False` 关闭。
- 删除后保证段落通顺：若被删 segment 是段落唯一内容 → 用兜底句替换。
- 输出末尾附审计元数据（anchor 列表、每个 claim 的 verdict/degrade_reason），供前端/日志使用，
  **不展示给用户**。

## 5. 验收

1. 单元测试覆盖 A/B/C/D 四种情况、全删兜底、narrative 保留、删句省略标记、审计元数据、确定性重复一致。
2. 阶段一测试：superseded/未来/污染/预算溢出各 1 正 1 反；dropped 审计完整；相关性尾部删除按 25% 档；
   不得用"词面零交集"判据。
3. 阶段三不得绕过 `enforce()`（测试断言：伪造引用一定被删除）。
4. B 的三种原因（over_citation / scenario_superseded / argument_mismatch）措辞互不相同且为短说明。
5. 默认行为不变：不启用三阶段时，现有 `registers.render()` 行为逐字节不变。
