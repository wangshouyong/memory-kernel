# memory-kernel — 面向长期记忆的确定性引用执法

> [English](README.md) | 简体中文

> **这是什么**：一个零依赖的小内核，让 AI 助手的**引用可被机械核验**。
> 它提供两件事：(1) 只追加、可防篡改的证据账本；(2) 确定性执法层，逐条判定 `(断言, 引用)`——
> 伪造引文、否定翻转、时间倒置、说话人不匹配、已过时/被取代的证据、冗余引用。
> **这不是什么**：不是记忆数据库，不是检索系统，也不是托管产品。

- 许可证：代码 **Apache-2.0**，文档 **CC-BY-4.0**。
- 纯 Python 标准库；无网络；执法路径中不含任何模型。
- 版本 0.x：契约可能演进；每次契约变更都带版本号。

## 为什么

LLM 助手会引用"证据"，但多数系统从不核验。这个内核把核验变成机械、可复现的过程：账本说明有哪些证据（且未被改过），执法层判定引用是否合法/相关，发射门控在用户看到之前改写模型输出（加限定、删除、标未验证）。

## 与主流记忆架构的区别

主流"记忆"系统优化的是**上下文效率**：摘要旧对话、把事实抽取进图/向量库、压缩并检索片段，以便塞进更多历史。本内核优化的是**断言完整性**：每条断言是否能追溯到不可变证据，并在用户看到前被机械核验。两者互补，而非竞争。

| 维度 | 主流记忆（摘要 / 抽取 / 压缩 / RAG） | memory-kernel |
|---|---|---|
| 优化目标 | token 效率、召回、持久化 | 可审计、拒答正确性、可复现 |
| 存储模型 | 可变的摘要 / 抽取事实 / 向量块 | 只追加、哈希链证据账本（L0）；派生层允许但必须标"派生" |
| 更新语义 | 覆盖 / 合并 / 后写胜 | 追加 + 显式更正/取代事件；历史事实与"当前依据"分离 |
| 检索 | 内置 embedding / BM25 / 重排 | 外部、可替换；内核与检索器无关 |
| 模型输出 | 自由文本 | 按段给断言 + 逐字引文；无证据 → 显式未验证 |
| 判定方式 | 无核验，或用另一个 LLM 当裁判 | 仅确定性谓词——执法路径中不含模型 |
| 典型失效模式 | 流畅但不可核验；证据静默丢失；旧事实被当当前事实 | 加限定 / 拒答 / 改写；显式标未验证 |
| 成本画像 | 上下文便宜 | 更多 token 与存储，外加毫秒级门控；**没有压缩收益** |
| 规模 | 向量库可到十亿级 | 是内核不是数据库：8k 消息 demo 可用；100k 需要索引工程 |

**优势**

- **可核验、可复现**：伪造引文、否定翻转、时间倒置、说话人不匹配、残缺回答、被取代证据都会被确定性抓住。
- **证据不会静默丢失**：原文永不改写，更正是事件而非变更。
- **与模型无关、可离线**：纯标准库；同一门控可配任意生成器与检索器。
- **显式不确定性**：没有引用就是"未验证"；降级断言以限定措辞呈现，而不是悄悄放行。
- **历史与当前分离**："当时是什么"与"当前依据是什么"都能回答，且不撒谎。

**局限（采用前必读）**

- **没有效率收益**：这不是摘要器/压缩器。存储与生成 token 会更多，另有少量门控开销。
- **不是语义裁判**：逐字但语义无关的引用仍能通过机械核验；不保证真值。见 `docs/ALGO-CEILING.md`。
- **需要模型配合**：结构化逐段输出 + 逐字引文；自由文本无法执法。
- **不是记忆数据库**：检索质量、索引、规模与延迟仍是你的系统的责任。参考检索器用词面：cross-encoder 精排与全跨会话 dense 融合在我们的数据上为负；**条件 dense 路由**（偏好守卫，n=150 单次评测后作为默认配置）**不在**参考 demo 中。
- **集成与运维开销**：账本写入、引用锚点、密钥管理与审计面都要接进你的管线。

**适用**

- 受监管或企业知识助手，答案必须可审计。
- 高风险问答、合规记录、幻觉引用的复盘调试。
- 需要区分"用户说过什么 / 什么变了 / 现在是什么"的长期助手。
- 需要**本机可审计**来源溯源的共享记忆/多 Agent 场景（写入者/说话人元数据；**不承诺**第三方可验证归属——该能力不做）。
- 本地优先/离线部署（无网络，信任路径中无模型）。

**不适用**

- 消费级陪伴聊天：流畅、延迟、召回比引用完整性更重要。
- 大规模语义召回：瓶颈是索引与 ANN，不是核验。
- 无法要求引用、或没有可引证据的工作流。
- 想找记忆 API（Mem0、Zep、LangChain memory、向量库记忆）的即插即用替代品的团队——这是更底层，不是那个产品。

**与主流记忆结合**：可以把摘要器/抽取器放在上游——只要派生输出标"派生"、原文留在 L0。这样压缩无法销毁证据，抽取的事实只能**提议**、不参与**判定**（执法层保持确定性）。

```bash
python examples/dummy_retrieval/demo.py        # 账本 -> 检索 -> 执法，端到端
python -m unittest discover -s tests           # 运行测试
```

## 检索是商品化能力——执法才是资产

demo 带一个**参考检索器**（`examples/dummy_retrieval/`），让你不用写代码就能跑通；它是朴素 BM25 + 字符 n-gram + RRF，**不可用于生产**。换成 LangChain / LlamaIndex / Milvus / 你自己的向量库——执法层不关心证据是怎么检索来的：

```python
from dummy_retriever import BaseRetriever            # demo 只依赖这个接口
from langchain_community.vectorstores import Milvus  # 任意真实检索器
retriever = Milvus(embeddings=embeddings, connection_args={"host": "localhost", "port": "19530"})
hits = retriever.similarity_search(claim_text, k=10)  # 适配 BaseRetriever: index()/search()
```

- **不要**提 issue 抱怨自带 BM25 不够聪明。它存在的意义是让你 30 秒看到执法层在工作；检索质量由你负责。
- 自带检索器的**跨会话** recall@10 是本项目的 claim→evidence 探针（8,219 候选池）上的 **77.8%**。同会话 / in-sample 数字候选中位仅 8 条，**不作为能力指标**；以上数字均不构成对你语料的承诺。cross-encoder 精排与全跨会话 dense 融合在我们的数据上为负（偏好守卫的条件 dense 路由在 n=150 单次测试后已采纳，但**不在**参考 demo）。
- 上述"负结果"都源于本项目数据上的实际测量；记录这些方向是为了避免贡献者重复踩坑。

## 安全 / 伦理

- 执法层**不是**语义裁判："逐字但无关"的引用会通过机械核验。见 `docs/ALGO-CEILING.md`。
- 不要在 issue/PR 里放密钥或真实个人数据。
- 无担保。这是用于构建可审计性的基础设施，不是合规产品。
